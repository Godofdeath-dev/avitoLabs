# Лабораторная №3: координаты, очередь и worker pool

Только обязательная часть ТЗ: без батчей, приоритетной очереди, ретраев и rate limiter.

- [x] 1. Миграция trip_positions и last_position_at; модель и валидация координаты.
- [x] 2. POST/GET координат: транзакция, защита от опоздавших точек, сортировка и ошибки.
- [x] 3. SQL-выборка устаревших поездок, индекс и повторяемый EXPLAIN ANALYZE.
- [x] 4. HTTP-гейтвей Push Service: контракт, таймаут, ошибки, закрытие ответа.
- [x] 5. Сканер, ограниченный канал, фиксированные воркеры, дедупликация и отмена.
- [x] 6. Остановка, шесть обязательных метрик, span links, -race и goleak.
- [x] 7. Проверка живого сервиса под нагрузкой, медленного Push Service и SIGTERM; скриншот метрик.

## Автоматические проверки

Кодогенерация и golangci-lint проходят. Unit- и интеграционные тесты запускаются
с -race -count=2. Проверены транзакционный откат, опоздавшие точки, сортировка,
выборка свежих/завершённых/без координат, переполнение, отмена, ошибка Push Service,
фиксированное число воркеров, отсутствие перекрывающихся обходов и утечек горутин.

EXPLAIN на 6000 поездок: Index Scan using trips_status_position_time_idx,
фактически выбрано 10 строк. enable_seqscan не менялся. Проверка выполнена дважды.
Составной индекс использует status и время координаты; уточнение индекса оформлено
новой миграцией, ранее применённые миграции не редактировались.

## Окружение

environment.toml соответствует работе 3. Проверки на реальной БД выполнены сначала
на отдельном временном PostgreSQL, затем используется штатное окружение tripgo-lab-03.
Для запуска Push Service установлен официальный tripgoctl v0.1.2 во временном каталоге
WSL; проектный бинарник не заменялся. Рабочие данные других лабораторных не удалялись.
