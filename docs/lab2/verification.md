# Проверка лабораторной №2

Проверено локально на окружении `tripgo-lab-02` через `tripgoctl`.

- Unit-тесты: `go test -race -count=2 -coverprofile=coverage.out ./...`.
- Интеграция: `go test -race -count=2 -tags=integration ./...` с DATABASE_URL из `.env`.
- Линтер: полный обязательный набор из задания, включая depguard.
- HTTP: создание с нулевой ценой, получение, завершение; отдельные тесты проверяют ошибки.
- PostgreSQL: успешный цикл поездки, конфликт водителя и откат обеих таблиц.
- Корреляция: trace_id из лога находит HTTP-спан и дочерние SQL-спаны в Jaeger.
- Prometheus: длительность HTTP/БД, активные HTTP-запросы и счётчики поездок экспортируются.
- Отказ коллектора: отдельный экземпляр с OTLP-адресом 127.0.0.1:1 продолжает читать поездки.

Скриншоты для PR: [Jaeger](jaeger.png), [Grafana](grafana.png).
Дашборд можно импортировать из [grafana-dashboard.json](grafana-dashboard.json).
Числа на скриншотах — результаты тестовых запросов, а не нагрузочного теста.

## Границы работы

Состав метрик соответствует таблице §6.3 ТЗ лабораторной №2. Дополнительная
gauge активных поездок не реализуется по указанию пользователя.
Из репозитория удалён старый подсчёт метрик: запросы БД измеряются один раз,
на уровне пула через адаптер otelpgx.
